5.0— Wazuh Integration
    5.1 Wazuh Architecture
        Wazuh was integrated into the site-to-site VPN environment to provide centralized security monitoring of the Branch Windows endpoint from the HQ network.

        The Wazuh Manager is located within the HQ network at 10.10.10.2. The Windows endpoint is located within the Branch network at 10.20.20.5.

        The Windows endpoint runs the Wazuh Agent, which collects security-related events and forwards the telemetry to the Wazuh Manager. Because the endpoint and Wazuh Manager are located on separate networks, their communication traverses the WireGuard site-to-site VPN.

        The resulting architecture is:

        Plaintext
        Windows Endpoint (10.20.20.5)
            |
        Branch Network (10.20.20.0/24)
            |
        Branch Gateway (10.20.20.1)
            |
        WireGuard VPN
            |
        HQ Gateway (10.10.10.1)
            |
        HQ Network (10.10.10.0/24)
            |
        Wazuh Manager (10.10.10.2)
        This arrangement demonstrates the use of a VPN to securely connect a remote endpoint to centralized security monitoring infrastructure.

    5.2 Windows Agent Configuration
        The Wazuh Agent was deployed on the Windows endpoint located within the Branch network. The agent's local configuration file (ossec.conf) was modified to identify the HQ Wazuh Manager (10.10.10.2) as the destination for all collected security telemetry.

        The agent service was verified on the Windows endpoint to confirm that it was running correctly using PowerShell:

        PowerShell
        Get-Service -Name WazuhSvc
        A running WazuhSvc service confirms that the Wazuh Agent is operational on the endpoint and actively monitoring local events.

    5.3 Wazuh Communication Across the VPN
        The Wazuh Agent and Wazuh Manager are located on different network segments. The Branch Windows endpoint uses the Branch gateway as its route toward the HQ network. Traffic destined for the Wazuh Manager therefore follows the following path:

        Plaintext
        Windows Endpoint (10.20.20.5)
            |
            v
        Branch Gateway (10.20.20.1)
            |
            v
        WireGuard Tunnel
            |
            v
        HQ Gateway (10.10.10.1)
            |
            v
        Wazuh Manager (10.10.10.2)
        The WireGuard tunnel provides encrypted transport between the Branch and HQ gateways. This allows Wazuh telemetry generated by the Branch endpoint to reach the centralized Wazuh Manager without requiring the endpoint to be located directly on the HQ network.

    5.4 Agent Connectivity Verification
        After configuring the Wazuh Agent, its status was verified from the Wazuh Dashboard. The Windows endpoint successfully appeared in the Wazuh Manager as an active agent.

        The following information was used to validate the integration:

        Windows endpoint identified by the Wazuh Manager.

        Agent status displayed as "Active."

        Recent communication established between the agent and manager.

        Security events generated by the Windows endpoint appearing within the Wazuh dashboard environment.

        The active agent status provides concrete evidence that communication between the Branch endpoint and the HQ Wazuh Manager is fully operational.

    5.5 Security Event Generation
        A controlled Windows event [e.g., a simulated failed authentication attempt or service restart] was generated on the Branch endpoint to validate the complete monitoring pipeline.

        The purpose of the test was to confirm that an event generated on the remote endpoint could be collected by the Wazuh Agent and successfully received by the Wazuh Manager. The validation process consisted of:

        Plaintext
        Event Generated
            ↓
        Windows Endpoint
            ↓
        Wazuh Agent
            ↓
        Branch Gateway
            ↓
        WireGuard VPN
            ↓
        HQ Gateway
            ↓
        Wazuh Manager
            ↓
        Wazuh Dashboard
        The event was subsequently observed within the Wazuh environment. This confirmed that the Wazuh Agent was collecting endpoint telemetry and successfully communicating with the centralized Wazuh Manager.

    5.6 VPN Telemetry Correlation
        To further validate that Wazuh communication was traversing the WireGuard VPN, network traffic was correlated with the Wazuh event-generation test.

        WireGuard traffic counters were observed using sudo wg show. The test involved observing the initial WireGuard RX/TX counters, generating the controlled Windows event, and checking the counters again.

        Furthermore, as documented in Chapter 3, packet captures (tcpdump and Wireshark) were performed on the external WAN interface during the transmission of Wazuh telemetry. The correlation confirmed:

        Traffic Increase: An observable increase in RX/TX counters aligned precisely with the generation of the Wazuh alert.

        Payload Encapsulation: Packet captures verified that the Wazuh telemetry (normally transmitted over TCP port 1514) was successfully encapsulated and scrambled within WireGuard's UDP port 51820 transport data.

        This provides multiple layers of cryptographic and network validation rather than relying solely on the Wazuh Dashboard.

    5.7 Wazuh Integration Results
        The Wazuh integration successfully extended centralized security monitoring across the site-to-site VPN. The Branch Windows endpoint remained strictly on the Branch network while the Wazuh Manager remained isolated within the HQ network.

        The following capabilities were demonstrated:

        Wazuh Agent deployment on the Branch Windows endpoint.

        Successful communication between the Agent and Wazuh Manager.

        Routing of Branch-to-HQ traffic through the WireGuard VPN.

        Collection of a controlled Windows security event.

        Receipt and visualization of the event within Wazuh.

        Supporting evidence from WireGuard traffic counters and packet captures.

        The integration demonstrates that a remote endpoint can remain securely separated from the central monitoring network while continuously providing real-time security telemetry to the SOC infrastructure.
